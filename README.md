## Что это и для кого

Руководители крупной компании редко бывают аналитиками. SQL они не знают, в BI-систему ходить не хотят, а решение нужно принять здесь и сейчас. Обычный путь такой: написать аналитику, подождать отчёт, увидеть, что нужной метрики в нём нет, и написать снова.

Клодик убирает этот круг. Человек пишет в чат так, как написал бы коллеге:

> Покажи план-факт продаж по регионам за последний квартал

Через пару секунд он получает не текст и не картинку, а рабочий дашборд: KPI-карточки сверху, фильтры с поиском, переключатели разрезов и четыре связанных графика. Дальше дашборд дорабатывается тем же диалогом («добавь процент выполнения», «покажи только Центральный», «почему не выполнили план?»), сохраняется и потом открывается ровно в том же виде.

**Какие боли закрываем**

| Боль | Как закрываем |
|---|---|
| На каждый вопрос нужен поход в BI и заранее построенный отчёт | Бот сам находит данные и собирает дашборд по тексту вопроса |
| Нужной метрики в готовом отчёте нет | Вычисления добавляются диалогом поверх уже выгруженной таблицы, без нового похода в базу |
| Результат анализа теряется между сессиями | Дашборд сохраняется целиком (выборка, вычисления, раскладка, фильтры) и восстанавливается один в один |
| Непонятно, откуда взялась цифра и можно ли ей верить | Каждая цифра открывается щелчком: видно выборку, шаг и формулу |

## Что умеет

### Вопрос → дашборд

- Понимает русский язык с опечатками, разговорными формулировками, падежами и относительными периодами: «за последний квартал», «с марта по июнь 2025», «за год».
- Собирает дашборд из четырёх связанных панелей и KPI-карточек сверху. Панели такие: **план-факт по периоду**, **структура**, **ТОП** и **динамика выполнения**.
- Если значение неизвестно («покажи регион Сибирь-2»), переспрашивает и предлагает похожие варианты, а не рисует пустоту.
- Пустую выборку, обрезанный период и разное зерно плана и факта всегда объясняет текстом, а не прячет.
- Пишет короткое резюме с выводами: кто лидер, кто отстаёт, где аномалия. Выводы считает код, а не модель, поэтому цифры в тексте всегда совпадают с цифрами на графике.

### Вычисления диалогом

Вычисления устроены как **стек шагов** поверх выгруженной таблицы, данные при этом не правятся. Поэтому любой шаг можно отменить, заменить или откатиться к любой точке.

| Скажите | Что появится |
|---|---|
| «Добавь колонку с отклонением факта от плана» | отклонение, ₽ |
| «Посчитай процент выполнения плана» | выполнение, % |
| «Посчитай долю каждого региона в общем объёме» | доля, % |
| «Добавь динамику к предыдущему месяцу» | прирост к прошлому периоду, % |
| «Добавь накопительный итог по месяцам» | нарастающий итог |
| «Отсортируй по проценту выполнения и покажи ТОП-10» | ранг и сортировка |
| «Среднее / медиана / минимум / максимум по региону» | статистика по группе |
| «Поменяй формулу на …» | последняя колонка заменяется, новая не добавляется |
| «Перестрой график с учётом новой колонки» | панель рисует вычисленную колонку |
| «Отмени последнее вычисление» | шаг снимается со стека |

Формулы — это типизированные операции, `eval` нигде нет. Модель только выбирает операцию и её аргументы. Деление на нулевой план даёт пустое значение, а не бесконечность.

### Интерактив без модели и без базы

- **Фильтры с поиском и мультивыбором**: регион, город, тип точки, точка, категория, продукт.
- **Каскад** регион → точка и категория → продукт: если выбрать регион, в списке точек останутся только точки этого региона.
- **Переключатели**:
  - разрез;
  - метрика: план, факт, количество, скидки;
  - период: месяц, квартал, год;
  - вид: абсолютные значения, доля, прирост.
- **Синхронный зум**: если приблизить один график по времени, остальные приблизятся так же.
- При смене фильтра цифры KPI плавно перетекают к новому значению.

Всё это пересчитывается за 50–70 мс по таблице, которая уже лежит в памяти сессии. Модель и база при этом не вызываются ни разу, так что щёлкать можно сколько угодно бесплатно.

### Вопрос «почему?»: разбор причин

На вопрос «почему не выполнили план?» Клодик не сочиняет объяснение. Он **раскладывает разрыв между планом и фактом на вклады**: сколько недобрал каждый регион, точка и продукт. Результат он показывает двумя способами:
- панель-мост от плана к факту, вклады на которой в сумме сходятся до рубля;
- цепочка вглубь: регион → точка → продукт.

Аномалии в данных Клодик подсвечивает сам, без запроса.

### Видно, как посчитано

- **Ход работы потоком.** Пока бот думает, видно, что он делает прямо сейчас: понял вопрос, собрал выборку, посчитал, построил.
- **«Как это посчитано».** Щелчок по любой цифре открывает её происхождение: выборку, шаги вычислений и собранный SQL.
- **Режим «Показ».** Видимый курсор сам проводит по дашборду и по-настоящему выполняет разбор шаг за шагом, а подписи идут внизу экрана. Удобно на защите.

### Дашборд как пазл

- Панели **переносятся** мышью: соседи плавно разъезжаются, и панель встаёт на место, когда её отпускаешь.
- Если подержать панель на шапке другой, они **склеиваются** в одну коробку с вкладками. Кнопка «Разъединить» возвращает всё как было.
- Ширину панели можно менять. Панель можно убрать или собрать руками: разрез, метрика, вид графика.
- Дашборд раскладывается **по вкладкам**: чтобы перенести панель на другую вкладку, её перетаскивают на ярлык этой вкладки.
- Раскладка хранится в рецепте дашборда и переживает сохранение, перезагрузку и откат.
- Внизу слоя дашборда пристыкован чат. Вопрос уходит из него, и дашборд перестраивается за спиной, не закрываясь.

### Сохранение и история

- Сохранить, сохранить как, открыть, переименовать, скопировать, удалить: всё это можно сказать в чате или сделать кнопками.
- Список дашбордов с поиском и сортировкой. Запрос «Найди дашборд про скидки» ищет и по названию, и по тексту исходного вопроса, причём в любой форме слова («скидки», «скидок», «по скидкам»).
- **История версий** с откатом к любой версии.
- **Машина времени** внутри сессии: можно вернуться к любому шагу разговора.
- **Черновик в браузере**: если вкладку случайно закрыли, при следующем входе Клодик предложит продолжить.
- **Открытие по ссылке**: у сохранённого дашборда есть адрес, его можно отправить коллеге.

Сохраняются не данные, а **рецепт**: выборка, стек вычислений, раскладка, фильтры и переключатели. Это килобайты вместо мегабайтов, а при открытии дашборд оживает на актуальных данных.

### Выгрузка

- Дашборд целиком: **HTML** (открывается без интернета и без нашего сервера) или **картинкой**.
- Таблица: **CSV**, который открывается в Excel с правильной кодировкой.

### Клиенты и скидки

Плана по клиентам в данных нет. Поэтому вопросы вроде «покажи по клиенту Х за 3 года, какие скидки делались и почему» идут отдельной веткой: по факту, сегментам клиентов и причинам скидок, без плановых колонок. Код знает, что плана там нет, и не рисует фальшивое «выполнение».

### Честные ответы на неподходящие вопросы

- «Удали все продажи за 2025» или «обнули план»: Клодик вежливо отказывается, потому что данные доступны только для чтения.
- «Добавь фильтр с поиском»: это вопрос об интерфейсе. Клодик показывает, где фильтр уже есть, и не пытается его «исполнить».
- Если вопрос не про продажи, Клодик так и говорит.

### Внешний вид

- Тёплая палитра, светлая и тёмная тема.
- Свои шрифты лежат в репозитории, поэтому интерфейс работает в изолированном контуре без доступа к Google Fonts.
- Аккуратное движение на переходах, которое учитывает системную настройку «уменьшить движение».
- Интерфейс полностью на русском: подписи осей, легенды, названия метрик, сообщения бота.

## Как это устроено

```
  Веб (React + Plotly)          iOS (SwiftUI + WKWebView)
           │                              │
           └──────────────┬───────────────┘
                          │  один HTTP API
                ┌─────────▼──────────┐
                │      FastAPI       │
                │                    │         ┌──────────────┐
                │  Планировщик  ─────┼────────►│  OpenAI API  │
                │  (1 вызов модели)  │         └──────────────┘
                │        │ намерение и параметры
                │  Сборщик SQL  ─────┼────────►┌───────────────────────┐
                │        │           │         │ PostgreSQL 16         │
                │  Плоская таблица   │         │  данные — роль RO     │
                │        │           │         │  app.* — дашборды     │
                │  Стек вычислений   │         └───────────────────────┘
                │  (pandas)          │
                │        │           │
                │  Сборщик дашборда  │
                └────────┼───────────┘
                         ▼
          таблица + конфиг: KPI, фильтры, переключатели, 4 панели
```

### Поток одной реплики

1. **Планировщик** делает один вызов `gpt-4.1-mini` со строгой JSON-схемой. Модель возвращает только **намерение** и его параметры. Намерения бывают такие: новый вопрос, уточнение, фильтр, вычисление, сохранение, «почему», подсказка по интерфейсу, отказ. SQL, формулы и выводы модель не пишет.
2. **Сборщик SQL** по этим параметрам собирает один параметризованный `SELECT` только для чтения. Запрос исполняется под ролью `bi_reader` без прав на запись и с таймаутом.
3. **Плоская таблица** — одна денормализованная таблица на зерне `месяц × точка × продукт` с присоединёнными атрибутами. Из неё строятся все графики дашборда. Таблица живёт в памяти **сессии анализа**.
4. **Стек вычислений** — именованные шаги поверх таблицы. Сама таблица не меняется: при каждом изменении стек прогоняется заново, поэтому «отмени» и «поменяй формулу» работают честно.
5. **Сборщик дашборда** собирает KPI, фильтры, переключатели, спецификации четырёх панелей и текстовые выводы, посчитанные кодом.
6. **Клиент** только рисует. Фильтры, переключатели и зум уходят в `POST /api/view`. Он пересчитывает вид по таблице сессии за 50–70 мс, не обращаясь ни к модели, ни к базе.

### Что где считается

| Слой | Отвечает за | Не отвечает за |
|---|---|---|
| Модель | намерение и его параметры | SQL, формулы, тип графика, выводы |
| `sql_builder` | один SELECT только для чтения | агрегацию под вид |
| `aggregate` | окно, фильтры, группировку | отношения |
| `calculations` | стек шагов поверх агрегата | группировку |
| `diagnose` | разложение разрыва план-факт на вклады | слова объяснения |
| `dashboard` | 4 панели, KPI, фильтры, переключатели | числа «в обход» таблицы |
| `insights` | текстовые выводы кодом | вызовы модели |
| `store` | сохранённые дашборды и версии | данные: хранится только рецепт |
| Клиент | отображение, поиск в фильтре, зум, перенос | любой расчёт |

### Незыблемые принципы

- **Один API на все клиенты.** Веб и iOS — тонкие клиенты, бизнес-логики в клиенте нет.
- **Центральный объект — сессия анализа**, а не график и не сообщение. Сессия — это таблица, стек вычислений и конфиг дашборда.
- **Вычисления не в SQL.** Данные выгружаются один раз, и все расчёты идут поверх таблицы. Это прямое требование кейса.
- **Сгенерированное моделью не исполняется напрямую.** SQL собирает код, формулы — типизированные операции.
- **Цифры честные.** Неполный период, пустая выборка и разное зерно плана и факта обрабатываются явно.
- **Объяснения считает код.** Иначе цифры в тексте разойдутся с графиком, и проверить их будет нечем.

### Стек

| Слой | Технологии | Почему так |
|---|---|---|
| Backend | Python 3.13, FastAPI, pandas, Pydantic | pandas — естественное место для вычислений поверх таблицы |
| Данные | PostgreSQL 16 в Docker, русская ICU-коллация | 180 тыс. строк факта и джойны шести таблиц: колоночная СУБД добавила бы только сложность |
| NL-слой | OpenAI, `gpt-4.1-mini` | выбрана замером на 8 контрольных вопросах: 100% точности, 0,9 с, $0,58 за 1000 запросов против $3,20 у старшей модели |
| Web | React 18, TypeScript, Vite 6, Plotly.js | Plotly есть в реальном ТЗ заказчика, и совпадение стека важнее мелких выигрышей |
| iOS | SwiftUI + WKWebView | дашборд переиспользует веб-рендер, второй продукт не пишем |

Ответы планировщика кешируются на диске в `backend/.cache/planner.json`. Повторный вопрос отвечает мгновенно и не стоит ни копейки.

## Быстрый старт

Для тех, у кого уже стоят Docker, Python 3.12+ и Node 20+.

```bash
git clone https://github.com/has1l/sk.git && cd sk

cp .env.example .env                 # вписать OPENAI_API_KEY
# положить 8 CSV датасета в db/seed/ — см. db/seed/README.md

docker compose up -d                 # база на порту 5433; первая загрузка около минуты

cd backend
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/uvicorn app.main:app --port 8000 &

cd ../web
npm install && npm run dev           # http://localhost:5173
```

Откройте http://localhost:5173 и напишите «Собери дашборд по продажам».

## Запуск по шагам

### 0. Что нужно установить

| Инструмент | Версия | Проверка |
|---|---|---|
| Docker (Docker Desktop, Colima или OrbStack) | любая свежая с `docker compose` | `docker compose version` |
| Python | 3.12 или новее (разрабатывали на 3.13) | `python3 -V` |
| Node.js | 20 или новее (разрабатывали на 24) | `node -v` |
| Ключ OpenAI | с доступом к `gpt-4.1-mini` | — |
| Свободное место на диске | несколько гигабайт под образ Postgres и данные | `df -h` |

> На macOS с Colima: `brew install colima docker docker-compose && colima start`.

### 1. Склонировать и настроить окружение

```bash
git clone https://github.com/has1l/sk.git
cd sk
cp .env.example .env
```

Откройте `.env` и впишите свой `OPENAI_API_KEY`. Остальные значения можно оставить как есть, подробности в разделе [Переменные окружения](#переменные-окружения).

> `.env` лежит **в корне репозитория**, его читают и Docker, и бэкенд. В git он не попадает.

### 2. Положить данные

Датасет принадлежит заказчику и выдан участникам хакатона, поэтому в репозиторий он не входит. Скачайте его по ссылке из [`db/seed/README.md`](db/seed/README.md) и распакуйте так, чтобы в `db/seed/` оказались восемь файлов:

```
clients.csv  contracts.csv  discounts.csv  outlets.csv
products.csv  regions.csv  sales.csv  sales_plan.csv
```

Файлы нужны **до первого** `docker compose up`: база загружает их при инициализации.

### 3. Поднять базу

```bash
docker compose up -d
docker compose ps                    # ждём STATUS = healthy
```

При первом запуске по порядку выполняются скрипты из `db/init/`:

| Скрипт | Что делает |
|---|---|
| `01-schema.sql` | создаёт таблицы справочников, продаж, плана и скидок |
| `02-load.sql` | загружает 331 тыс. строк из CSV |
| `03-indexes-views.sql` | строит индексы, вьюху `plan_fact_flat` и витрину `client_fact_flat` |
| `04-roles.sh` | заводит роли `bi_reader` (только чтение данных) и `app` (только схема `app`) |
| `05-app-schema.sql` | создаёт схему `app` для сохранённых дашбордов и версий |

Проверьте, что данные на месте:

```bash
docker exec -e PGPASSWORD=bi_reader puzzle-db \
  psql -U bi_reader -d puzzle -c "SELECT count(*) FROM plan_fact_flat;"
```

Пересоздать базу с нуля (это сотрёт и сохранённые дашборды):

```bash
docker compose down -v && docker compose up -d
```

### 4. Запустить API

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/uvicorn app.main:app --port 8000
```

Для разработки удобно добавить `--reload`. Проверка:

```bash
curl http://127.0.0.1:8000/api/health
```

### 5. Прогреть кеш (рекомендуется перед демо)

```bash
cd backend
.venv/bin/python scripts/warm_cache.py
```

Скрипт прогоняет через планировщик все шаблонные и демо-вопросы, после чего они отвечают мгновенно и бесплатно. Запускайте его после любой правки системного промпта планировщика: отпечаток промпта входит в ключ кеша, поэтому правка обнуляет кеш целиком.

### 6. Запустить веб

```bash
cd web
npm install
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на `http://127.0.0.1:8000`, так что настраивать адрес API отдельно не нужно.

Продакшен-сборка:

```bash
npm run build        # проверка типов и сборка в web/dist
npm run preview      # посмотреть собранное
```

## Сценарий демо

Проверенный маршрут примерно на пять минут. Все вопросы взяты из раздела «Примеры запросов» кейса и уже прогреты в кеше.

**1. Дашборд из одной фразы**
> Собери дашборд по продажам: план-факт по регионам за последний год

Появляются KPI, фильтры, переключатели и четыре панели. Под ответом идёт резюме с лидером и отстающими.

**2. Интерактив без модели**
- В фильтре регионов наберите «сиб» и выберите Сибирский: KPI перетекают, все панели пересчитываются.
- Переключите период на кварталы, а метрику на количество.
- Приблизьте один график по времени: остальные приблизятся синхронно.

**3. Вычисления диалогом**
> Посчитай процент выполнения плана
> Добавь динамику к предыдущему месяцу
> Перестрой график с учётом новой колонки
> Поменяй формулу на отклонение факта от плана
> Отмени последнее вычисление

**4. «Почему?»**
> Почему не выполнили план?

Появляются панель-мост от плана к факту, вклады регионов и цепочка вглубь. Щелчок по цифре открывает «как это посчитано».

**5. Честность**
> Покажи выполнение плана за 2026 год

Клодик предупреждает, что факт обрывается 30 сентября, и сравнивает план только на горизонте факта.

> Удали все продажи за 2025 год

Вежливый отказ: данные доступны только для чтения.

**6. Клиенты и скидки**
> Покажи по клиенту … за последние 3 года, какие скидки делались и почему

**7. Пазл**

Перенесите панель на другое место, затем подержите её на шапке соседней, и они склеятся вкладками. Разложите дашборд по вкладкам.

**8. Сохранение**
> Сохрани как "Продажи Q3"
> Покажи мои дашборды
> Найди дашборд про скидки

Перезагрузите страницу и откройте «Продажи Q3»: всё на месте, включая раскладку и фильтры. Скачайте HTML и CSV.

**9. Режим «Показ»**

Нажмите «Показ»: курсор сам пройдёт по дашборду и объяснит, что на нём видно.

## Данные и три ловушки

Продажи FMCG-дистрибьютора за 2023–2026 годы.

| Что | Сколько |
|---|---|
| Регионы | 8 |
| Торговые точки | 300 |
| Продукты | 42 |
| Клиенты | 180 |
| Продажи | около 179 тыс. строк |
| План | около 122 тыс. строк (`месяц × точка × продукт`) |
| План всего | 4 082 млн ₽ |
| Факт всего | 3 377 млн ₽ |
| Период факта | 2023-01-01 … 2026-09-30 |
| Период плана | 2023-01 … 2026-12 |

В данных три ловушки. Каждая даёт правдоподобный, но неверный график, поэтому все три обработаны явно.

1. **2026 год неполный.** Факт обрывается 30 сентября, а план размечен до декабря. Наивное «выполнение за 2026» получается 65,4%, но это не провал, а три отсутствующих месяца. Клодик ограничивает план горизонтом факта и говорит об этом текстом.
2. **План и факт не совпадают по ключам.** У 11 711 комбинаций `месяц × точка × продукт` есть план, но нет продаж, это 445 млн ₽. `INNER JOIN` молча выбросил бы 11% плана, и выполнение подскочило бы примерно с 83% до 93%. Поэтому используется только `FULL OUTER JOIN`, а отсутствующая сторона считается нулём.
3. **Факт мельче плана.** На один ключ плана приходится несколько продаж по разным договорам и клиентам. Джойн «в лоб» размножил бы план. Поэтому факт агрегируется до зерна плана **до** соединения.

Плана по клиентам в данных нет совсем. Поэтому вопросы о клиентах и скидках идут через отдельную витрину `client_fact_flat` без плановых колонок.

Подробно — в [`docs/DATA.md`](docs/DATA.md).

## HTTP API

Один API на все клиенты, все пути начинаются с `/api`. Интерактивная документация FastAPI лежит на http://127.0.0.1:8000/docs.

### Разговор

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/ask` | принимает реплику пользователя, возвращает ответ бота и дашборд |
| `POST` | `/api/ask/stream` | то же потоком: сначала шаги хода работы, потом ответ |
| `GET` | `/api/templates` | шаблоны частых запросов |
| `GET` | `/api/health` | проверка живости |

Тело запроса к `/api/ask`: `{"question": "…", "session_id": "…"}`. Без `session_id` начинается новая сессия, длина вопроса — до 1000 символов.

### Сессия анализа

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/session/{id}` | текущее состояние сессии |
| `POST` | `/api/view` | фильтры, переключатели, зум: пересчёт без модели и без базы |
| `POST` | `/api/session/{id}/undo` | отменить последний шаг |
| `POST` | `/api/session/{id}/rewind/{snapshot_id}` | машина времени: вернуться к снимку |
| `DELETE` | `/api/session/{id}/step/{step_id}` | убрать конкретный шаг вычислений |
| `POST` | `/api/draft/restore` | восстановить черновик из браузера |

### Раскладка и панели

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/layout` | сохранить порядок, ширину, склейки и вкладки панелей |
| `GET` | `/api/panel-options` | варианты для ручной сборки панели |
| `POST` | `/api/session/{id}/panel` | добавить собранную вручную панель |
| `DELETE` | `/api/session/{id}/panel/{panel_id}` | убрать панель |

### Сохранённые дашборды

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/dashboards` | список |
| `POST` | `/api/dashboards` | сохранить текущий |
| `GET` | `/api/dashboards/{id}/open` | открыть |
| `PATCH` | `/api/dashboards/{id}` | переименовать |
| `POST` | `/api/dashboards/{id}/copy` | скопировать |
| `DELETE` | `/api/dashboards/{id}` | удалить |
| `GET` | `/api/dashboards/{id}/versions` | история версий |
| `POST` | `/api/dashboards/{id}/versions/{version}/open` | открыть версию |

### Выгрузка

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/export/csv/{session_id}` | таблица в CSV |
| `GET` | `/api/export/html/{session_id}` | дашборд одним HTML-файлом |

Пример:

```bash
curl -s http://127.0.0.1:8000/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "Покажи план-факт по регионам за последний квартал"}' | head -c 400
```

## Безопасность

| Риск | Что сделано |
|---|---|
| Утечка ключа OpenAI | ключ лежит только в `.env` на сервере, в клиент и в `VITE_*` не попадает; `.env` и любые `.env.*`, кроме шаблона, есть в `.gitignore` |
| Модель напишет опасный SQL | модель SQL не пишет вовсе; его собирает код как один параметризованный `SELECT` с таймаутом, значения уходят параметрами, а не в текст запроса |
| Запрос изменит данные | все запросы из вопросов идут под ролью `bi_reader` без прав на запись; просьбы вроде «удали продажи» распознаются и отклоняются |
| Модель выполнит произвольный код | формулы — типизированные операции из фиксированного списка, `eval` нигде нет |
| Скрипт выжжет бюджет API | лимит вопросов к модели с одного адреса в минуту (`ASK_PER_MINUTE`) и кеш ответов |
| Внутренности в сообщениях об ошибках | клиент получает понятный человеку текст, подробности пишутся только в лог сервера |
| Уязвимые зависимости | `npm audit` показывает 0 уязвимостей; находки bandit разобраны: B608 ложные, поля SQL берутся из белого списка |
| Данные заказчика в публичном репозитории | CSV датасета и кеш планировщика есть в `.gitignore` |

Сложной системы прав в проекте нет сознательно: кейс её исключает. Для публичного развёртывания понадобятся как минимум вход по паролю и общий дневной лимит расхода ключа.

## Частые проблемы

**Контейнер базы падает с `could not open file "/seed/regions.csv"`.**
CSV не лежат в `db/seed/`. Положите файлы, затем выполните `docker compose down -v && docker compose up -d`.

**API висит, в логе `PoolTimeout` или ошибки ввода-вывода Postgres.**
Чаще всего кончилось место на диске. Освободите место, перезапустите Docker (`colima restart` или перезапуск Docker Desktop), затем выполните `docker compose up -d`.

**`address already in use` на порту 8000.**
Остался старый процесс uvicorn. Выполните `lsof -ti :8000 | xargs kill` и запустите снова.

**Порт 5433 занят.**
Поменяйте `POSTGRES_PORT` в `.env`: бэкенд берёт значение оттуда же.

**Бот отвечает «Не удалось разобрать вопрос».**
Нет ключа OpenAI, у ключа нет доступа к модели или нет сети. Проверьте `OPENAI_API_KEY` в корневом `.env` и перезапустите API.

**«Слишком много вопросов подряд — подождите минуту».**
Сработал лимит `ASK_PER_MINUTE`. Для локальных прогонов его можно поднять в `.env`.

**Демо-вопросы вдруг стали медленными.**
Кеш планировщика обнулился после правки промпта. Прогоните `backend/.venv/bin/python backend/scripts/warm_cache.py`.

**Русские названия в фильтрах сортируются странно.**
База создана без ICU-коллации, например вручную, а не через `docker-compose.yml`. Пересоздайте её: `docker compose down -v && docker compose up -d`.

**Сессия «потерялась» после перезапуска API.**
Сессии анализа живут в памяти процесса. Сохранённые дашборды при этом лежат в базе и открываются как обычно, а несохранённую работу веб предложит восстановить из черновика.
