# Карта контекстов

Три области, связанные одним HTTP API. Бизнес-логики в клиентах нет — они рисуют то, что отдал сервер, и обрабатывают интерактив поверх уже выгруженной таблицы.

| Область | Папка | Отвечает за | Глоссарий |
|---|---|---|---|
| Backend | `backend/` | Разбор запроса на русском, построение SQL, выгрузка плоской таблицы, стек вычислений, сборка конфига дашборда, хранение дашбордов | `backend/CONTEXT.md` |
| Web | `web/` | Лента чата, рендер дашборда на Plotly, фильтры и переключатели, клиентский пересчёт KPI, список дашбордов | `web/CONTEXT.md` |
| iOS | `Zura/` | Нативная оболочка: чат, список дашбордов, вход. Дашборд — веб-рендер внутри WKWebView | `Zura/CONTEXT.md` |

**Связи:**
- Web и iOS ходят в один и тот же API бэкенда. Контракт один, версий клиентов две.
- iOS переиспользует веб-рендер дашборда — поэтому веб-дашборд обязан быть адаптивным с самого начала.
- Домен (план, факт, разрез, метрика, зерно) определён в `backend/CONTEXT.md` и является общим для всех областей. Клиентские глоссарии описывают только свои термины (состояние фильтра, лента, карточка дашборда).

Термины датасета — `docs/DATA.md`. Требования — `docs/CASE.md`.
