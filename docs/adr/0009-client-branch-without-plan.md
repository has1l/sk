# ADR-0009: Клиенты — отдельная ветка выборки, только факт

Status: accepted
Date: 2026-11-14

## Context

Кейс называет клиента среди фильтров («регион, точка, продукт, клиент, период»)
и даёт демо-вопрос «Покажи по клиенту Х за последние 3 года, какие скидки
делались и почему». Плоская таблица `plan_fact_flat` клиента не знает: план
ставится на «месяц × точка × продукт», клиента и договора в нём нет
(`docs/DATA.md`, ловушка 3). Опустить таблицу до зерна клиента нельзя — план
пришлось бы делить между клиентами по выдуманному правилу.

До этого решения вопрос про клиента молча терял фильтр и показывал дашборд по
всей базе: ответ выглядел как ответ про клиента и был ложью.

Варианты:
1. Распределить план по клиентам пропорционально их факту. Даёт «выполнение»
   у каждого клиента ровно равное выполнению точки — число без смысла.
2. Отдельный запрос в обход таблицы сессии. Ломает принцип «все графики из
   одной таблицы» и весь интерактив поверх неё (ADR-0006).
3. Вторая плоская таблица на зерне факта с той же формой колонок и нулевым
   планом; код знает, что плана в ней нет.

## Decision

Вариант 3. Материализованная вьюха `client_fact_flat` на зерне «месяц × точка ×
продукт × клиент × причина скидки». Скидка одна на продажу, поэтому причина —
атрибут продажи, и факт по причинам складывается без двойного счёта. Итог
факта совпадает с `plan_fact_flat` до копейки.

Источник выбирает код (`sql_builder.source_for`), а не модель: клиентская
ветка включается, если в разрезах или фильтрах есть клиент, сегмент клиента
или причина скидки (`Dimension.is_fact_only`). Таблица сессии получает три
лишние колонки; признак ветки — наличие `client_name` (`aggregate.is_fact_only`).

Дашборд в этой ветке не показывает ничего про план: KPI — факт, скидки, доля
скидок, сделки, динамика, активные клиенты; панель 1 — только факт; панель 4 —
доля скидок по периодам вместо выполнения; моста нет. Плановые метрики
выбрасываются из заказа выборки, чтобы в таблице не стояло «План 0».

Фильтр по клиенту в обычной сессии перегружает выборку из клиентской ветки,
стек и раскладка сохраняются. Названное, но не найденное значение фильтра —
повод переспросить, а не строить дашборд по всем данным.

## Consequences

- «Выполнение плана по клиентам» невозможно и не притворяется возможным —
  бот говорит, что плана по клиентам нет.
- Вьюха материализована: данные статичны. Обновятся — `REFRESH MATERIALIZED
  VIEW client_fact_flat` вместе с `sales_monthly`.
- 157 тыс. строк без фильтров — укладывается в потолок таблицы сессии.
- Новые разрезы обязаны иметь запись во всех словарях подписей `labels.py`.
