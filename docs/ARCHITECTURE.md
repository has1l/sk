# Архитектура

## Общая схема

```
  Web (React+Plotly)        iOS (SwiftUI + WKWebView)
          │                            │
          └────────────┬───────────────┘
                       │  один HTTP API
              ┌────────▼─────────┐
              │  FastAPI         │
              │                  │
              │  ┌────────────┐  │        ┌──────────────┐
              │  │ Планировщик├──┼───────►│  OpenAI API  │
              │  │ запроса    │  │        └──────────────┘
              │  └─────┬──────┘  │
              │        │ спецификация выборки
              │  ┌─────▼──────┐  │        ┌──────────────────┐
              │  │ Сборщик SQL├──┼───────►│ PostgreSQL       │
              │  └─────┬──────┘  │        │  данные (RO роль)│
              │        │ плоская таблица  │  app.* (дашборды)│
              │  ┌─────▼──────────────┐   └──────────────────┘
              │  │ Стек вычислений    │  │
              │  │ (pandas)           │  │
              │  └─────┬──────────────┘  │
              │  ┌─────▼──────────────┐  │
              │  │ Сборщик дашборда   │  │
              │  └─────┬──────────────┘  │
              └────────┼─────────────────┘
                       │ таблица + конфиг дашборда
                       ▼
             клиент рендерит и держит интерактив
```

## Поток одного запроса

1. **Планировщик запроса.** Текст на русском + схема данных + контекст диалога → спецификация выборки: какие разрезы, какая метрика, какой период, какое зерно. Если данных для ответа не хватает — возвращает уточняющий вопрос вместо спецификации.
2. **Сборщик SQL.** Спецификация → параметризованный SELECT. SQL собирается кодом по спецификации, а не пишется моделью напрямую.
3. **Плоская таблица.** Одна денормализованная таблица на зерне `месяц × точка × продукт` (см. `docs/DATA.md`), уже с присоединёнными атрибутами. Все графики дашборда строятся из неё.
4. **Стек вычислений.** Именованные шаги поверх таблицы: добавить колонку, изменить формулу, откатить. Таблица пересобирается прогоном стека, а не мутируется.
5. **Сборщик дашборда.** Конфиг: KPI-карточки, фильтры, переключатели, спецификации графиков. Данных в конфиге нет — только описание, как читать таблицу.
6. **Клиент.** Рендерит таблицу и конфиг. Фильтры, переключатели, зум, пересчёт KPI — всё локально, без обращения к серверу.

## Что где считается

| Операция | Где | Почему |
|---|---|---|
| Выборка и агрегация до зерна | PostgreSQL | там, где данные |
| Добавление колонки с вычислением | Сервер, pandas | требование кейса: вычисления после выгрузки, не в SQL |
| Фильтрация, переключение разреза, зум | Клиент | мгновенно, без запроса и без токенов |
| Пересчёт KPI под фильтром | Клиент | те же данные, что у графиков |
| Текстовое резюме с инсайтами | Сервер + OpenAI | по агрегатам, не по сырым строкам |

## Что сохраняется в дашборде

Не данные, а рецепт: спецификация выборки, стек вычислений, конфиг дашборда, состояние фильтров и переключателей, название и даты. Восстановление — повтор выборки и прогон стека. Килобайты вместо мегабайтов, и дашборд оживает на актуальных данных.

## Ограничение размера

Плоская таблица уезжает на клиент целиком — значит она должна быть подъёмной. Потолок ~50 000 строк. Зерно выбирает планировщик: для «по регионам по месяцам за год» это 8 × 12 = 96 строк, для «по точкам по месяцам» — 300 × 12 = 3 600. Если спецификация даёт больше потолка — сервер сужает зерно и говорит об этом, а не отдаёт молча.

## Поток реплики после среза 2

```
реплика → planner.interpret (1 вызов модели) → намерение
                                                   │
        ┌──────────────────────────────────────────┼───────────────────────┐
        │                      │                   │                       │
   новый вопрос           вычисление          переключатель            сохранение
   правка выборки         откат               фильтр                   открытие
        │                      │                   │                       │
   SQL → таблица          шаг в стек        ViewState            схема app (jsonb)
   сессии                                         │                       │
        └──────────────────────────────────────────┴───────────────────────┘
                                   │
                            render.build
                  таблица + 4 панели + KPI + выводы
```

**Интерактив** (`POST /api/view`) минует и модель, и базу: пересчёт идёт по датафрейму сессии в памяти, 50–70 мс ([ADR-0006](adr/0006-interactive-recompute-on-the-server.md)).

**Что где считается**

| Слой | Отвечает за | Не отвечает за |
|---|---|---|
| Модель | намерение и его параметры | SQL, формулы, тип графика, выводы |
| `sql_builder` | один read-only SELECT | агрегацию под вид |
| `aggregate` | окно, фильтры, группировка | отношения |
| `calculations` | стек шагов поверх агрегата | группировку |
| `dashboard` | 4 панели, KPI, фильтры, переключатели | числа «в обход» таблицы |
| `insights` | текстовые выводы кодом | вызовы модели |
| `store` | сохранённые дашборды и версии | данные (хранится рецепт) |
| Клиент | отображение, поиск в фильтре, зум | любой расчёт |
