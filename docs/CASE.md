# Кейс: чат-бот с интерактивной визуализацией данных

> Источник истины по требованиям. Не редактируем под то, что успели сделать — сюда смотрим, чтобы понять, что от нас хотели.

**Заказчик:** Puzzle RPA (ООО «ПУСК») — автоматизация крупных организаций программными роботами и чат-ботами с ИИ. Клиенты: ФНС, 1С, ИВИ, Петрович, крупные банки. Кейс основан на реальном ТЗ; решения команд могут быть добавлены в платформенные решения и отгружены ключевым клиентам.

## Легенда

Крупная компания использует чат-бот для внутренних коммуникаций. Руководители и менеджеры хотят получать ответы на аналитические вопросы сразу в чате, без похода в BI-систему. Например: «Покажи план-факт продаж по регионам и торговым точкам за последний квартал».

Сейчас бот умеет только отвечать текстом. Нужно научить его работать с данными и строить интерактивные дашборды по текстовому запросу.

**Почему не Power BI / Superset:**
- BI требует заранее построенных отчётов и «похода» за ними.
- Нужен ответ здесь и сейчас для управленческого решения.
- Нужной информации в готовых BI-отчётах может не быть.
- BI остаётся для стандартных метрик; ad-hoc аналитика уходит в чат-бот.

## Суть

Пользователь пишет текстовый запрос → бот сам находит данные в базе → формирует единую таблицу для визуализации → строит дашборд из нескольких интерактивных графиков с фильтрами и итоговыми цифрами → отображает в чате → сохраняет дашборд, чтобы можно было вернуться позже.

**Ключевая особенность: работа с данными — это диалог.** Пользователь может попросить показать таблицу, добавить колонку с вычислением, изменить формулу, пересчитать, и только потом строить графики — или перестраивать уже построенные с учётом новых вычислений.

## Минимальный результат (MVP)

1. Пользователь вводит вопрос на естественном языке.
2. Бот понимает, что нужна визуализация.
3. Бот сам достаёт нужные данные из базы.
4. Бот формирует единую таблицу и показывает её.
5. Бот строит один интерактивный график по этой таблице.
6. График появляется в чате: зум, курсор, переключение легенды.
7. Дашборд можно сохранить и вернуться к нему позже.

## Целевой результат

- Дашборд из 4 графиков по одному запросу.
- Фильтры (выпадающие списки с поиском) и переключатели.
- Сверху — итоговые цифры (ключевые метрики).
- Пользователь может запросить вычисления и добавить их колонками.
- Пользователь может перестраивать графики после добавления вычислений.
- Графики связаны: единый стиль, общие оси, согласованные цвета.
- Бот уточняет запрос, если данных недостаточно.
- Бот добавляет текстовое резюме с ключевыми инсайтами.
- Дашборды сохраняются, есть список, можно вернуться к любому.

## Работа с данными и вычислениями

**Главный принцип: все вычисления делаются на стороне бота после выгрузки данных, а не в SQL-запросе.** Это позволяет менять логику расчётов без повторных запросов к базе.

Цикл: выгрузка плоской таблицы → показ таблицы → добавление вычислений → пересчёт и перестройка графиков → итерации без ограничения количества.

**Примеры вычислений:** отклонение факта от плана (абсолютное и в процентах); процент выполнения плана; динамика к предыдущему периоду (MoM, YoY); доля в общем объёме (по региону, продукту, точке); накопительный итог; среднее, медиана, min/max по группе; ранжирование (ТОП-N); произвольная формула («факт минус план, делить на план, умножить на 100»).

**Важно:** пользователь не пишет код — он формулирует вычисление на естественном языке.

## Интерактивность дашборда

**Фильтры:** выпадающие списки по ключевым разрезам (регион, точка, продукт, клиент, период); поиск значения внутри фильтра (до 500 точек); множественный выбор; каскадные фильтры (регион сужает список точек) — бонус; применяются ко всем графикам одновременно.

**Переключатели:** разрез (регионы / точки), метрика (объём / скидка / количество сделок / % выполнения), период (месяц / квартал / год), вид (абсолютные значения / проценты / динамика).

**KPI-карточки сверху:** общий план; общий факт; процент выполнения; отклонение абсолютное и в процентах; количество активных клиентов / точек / продуктов; динамика к предыдущему периоду. Требования: крупные читаемые цифры, подписи на русском, цветовая индикация (зелёный — выполнение, красный — отставание), обновление при изменении фильтров.

## Сохранение дашбордов

**Что сохраняется:** запрос пользователя; единая таблица с данными и всеми вычислениями; конфигурация графиков (типы, разрезы, метрики, сортировки); настройки фильтров и переключателей на момент сохранения; KPI-карточки; даты создания и изменения; название (бот предлагает, пользователь может переименовать).

**Список дашбордов:** название, дата создания, дата изменения, краткое описание (запрос); сортировка по дате и названию; поиск по названию и по тексту запроса; открыть, удалить, переименовать.

**Возврат:** восстанавливаются таблица с вычислениями, графики в той же конфигурации, фильтры и переключатели в том же состоянии, KPI. Можно продолжить работу и сохранить как обновление или как новый дашборд.

**Сценарии:** вернуться к утреннему дашборду, чтобы показать коллеге; доработать дашборд; сделать копию для экспериментов; найти дашборд по тексту запроса, если забыл название.

## Пример целевого дашборда

Запрос: «Собери дашборд по продажам: план-факт по регионам и торговым точкам за последний год».

- **KPI-карточки:** План 1 250 000 000 ₽ · Факт 1 087 500 000 ₽ · Выполнение 87% · Отклонение −162 500 000 ₽ · Динамика к прошлому году +12%
- **Фильтры:** период; регион (мультивыбор с поиском); торговая точка (мультивыбор с поиском, каскадно от региона); продукт (мультивыбор с поиском)
- **Переключатели:** разрез (регионы/точки), метрика (объём/скидка/количество), период (месяц/квартал/год)
- **Графики (4):**
  1. План-факт по периодам — столбчатая, две серии
  2. Структура продаж за последний период — круговая
  3. ТОП регионов/точек — горизонтальные столбцы, сортировка по отклонению или объёму
  4. Динамика выполнения плана — линейный, с отметкой 100% и зонами пере/недовыполнения

**Развитие сценария:** «Добавь колонку с процентом выполнения плана» → «Перестрой третий график — отсортируй по проценту выполнения» → «Добавь вычисление динамики к прошлому месяцу» → «Покажи четвёртый график с учётом динамики» → фильтр по Центральному региону → переключение разреза на точки → «Сохрани дашборд под названием "Продажи Q3"» → позже «Покажи мои дашборды».

## Сверх MVP (для сильных команд)

Уточняющие запросы в контексте диалога · текстовое резюме с инсайтами · скачивание дашборда картинкой или HTML · скачивание таблицы CSV/Excel · автосохранение черновика · история версий с откатом · публикация по ссылке · шаблоны частых запросов · каскадные фильтры · синхронный зум между графиками.

## Ограничения

**Что не нужно делать:** подключать реальные корпоративные системы; реализовывать сложную систему прав доступа; делать дашборд из 10+ графиков; делать realtime-совместную работу.

**На что обратить внимание:**
- **Безопасность:** не позволять генерируемому коду делать лишнее — удалять, изменять данные, ходить в сеть.
- **Таймаут:** код не должен исполняться бесконечно.
- **Пустые данные:** график не должен падать, если данных нет.
- **Русские подписи:** оси, заголовок, легенда.
- **Единый стиль:** все графики дашборда выглядят как одно целое.
- **Единая таблица:** все графики строятся из одной таблицы.
- **История изменений:** пользователь понимает, какие вычисления добавлены и что можно отменить.
- **Производительность фильтров:** поиск в списке с большим числом значений работает быстро.
- **Сохранение:** дашборд восстанавливается в том же виде.

## Связь с реальным ТЗ

| В реальном проекте | У нас |
